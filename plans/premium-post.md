# Публикация через Telegram-аккаунт

## Итоговая оценка

Это задача средней сложности: базовая MTProto-инфраструктура уже есть, поэтому отдельный Python/Telethon-сервис не понадобится.

- Прототип: около 1 дня.
- Надёжная прод-реализация с тестами и защитой от дублей: 3–5 рабочих дней.
- Режим включается отдельно для каждого канала.
- Используется текущий подключённый аккаунт.
- Поддерживаются текст, фото, видео, GIF и альбомы до 10 элементов.
- Обычный аккаунт получает подпись до 1024 символов, Premium — до 4096. Для более длинного текста медиа и сообщение останутся раздельными. Это актуальные серверные лимиты Telegram: [Client configuration](https://core.telegram.org/api/config).

## Реализация

- Добавить назначению nullable-связь `publisher_telegram_account_id`: `null` означает текущий Bot API, выбранный аккаунт — MTProto.
- Сохранять у Telegram-аккаунта `is_premium` и время последней проверки. Обновлять данные через `getSelf` при авторизации, проверке назначения и публикации.
- В админке заменить сырой выбор в `settings` на понятный переключатель «Bot API / Telegram-аккаунт». Проверка назначения должна подтверждать:
  - активную MTProto-сессию;
  - права владельца либо администратора с `post_messages`;
  - текущий Premium-статус и применяемый лимит подписи.
- Расширить существующий `telegram-owner` новой командой `PublishDelivery`. `PublishDeliveryJob` продолжит синхронно отправлять Bot API-публикации, а аккаунтные будет передавать owner-worker.
- Связать owner-команду с `Delivery` уникальным nullable `delivery_id`. Успех завершает публикацию через существующий `CompleteDeliveryPublication`; активная команда исключает ложное срабатывание десятиминутного watchdog.
- Отправлять через `messages.sendMessage`, `messages.sendMedia` и `messages.sendMultiMedia`. TelegramApiServer уже поддерживает полное API и загрузку файлов: [TelegramApiServer README](https://github.com/xtrime-ru/TelegramApiServer#uploading-files).
- Перед первой попыткой зафиксировать в payload эффективный лимит подписи — 1024 или 4096. Повторные попытки используют то же решение, даже если Premium-статус изменился между попытками.
- Сохранять отдельный стабильный `random_id` для каждого сообщения и элемента альбома. Telegram дедуплицирует повторные вызовы с тем же идентификатором, поэтому обрыв после фактической отправки не создаст копию: [Working with Updates](https://core.telegram.org/api/updates).
- Для медиа использовать выделенный staging-каталог, доступный контейнеру `telegram-api` только для чтения. Файлы и превью удалять после подтверждённой отправки; текущий лимит приложения 50 МБ не расширять в этой задаче.
- Повторять сетевые ошибки, серверные ошибки и `FLOOD_WAIT` с указанной Telegram задержкой. Ошибки прав, недоступный канал и невалидное медиа завершать без повторов. Ручный retry обязан повторно использовать прежние `random_id`.
- Исходящие MTProto-события не попадут обратно в сборщик: текущий обработчик уже отбрасывает сообщения с `out=true`.

## Проверка

- Bot API остаётся поведением по умолчанию для существующих назначений.
- Обычный аккаунт: подпись 1079 символов публикуется отдельно от медиа.
- Premium: 1079 и 4096 символов публикуются одной медиаподписью; 4097 — отдельным текстом.
- Проверить текст без медиа, одиночные фото/видео/GIF, смешанный фото-видео альбом, превью и HTML-разметку.
- Проверить отсутствие дублей после таймаута, падения owner-worker и ошибки записи результата в БД.
- Проверить ошибки прав администратора, отключённую сессию, переключение назначения обратно на бота и watchdog активной публикации.
- Перед включением канала рецептов выполнить smoke-test в закрытом канале с подписью 1079 символов, большим видео и альбомом.

## Допущения и эксплуатация

- Текущий аккаунт будет администратором каналов назначения.
- При Premium подписи до 4096 будут единым постом; обычному аккаунту публикация разрешена, но лимит останется 1024.
- Публикация и загрузка исходных медиа используют одну owner-очередь текущего аккаунта, поэтому во время большого аплоада скачивание новых медиа этим аккаунтом может немного задерживаться.
- MTProto-сессия предоставляет полный доступ к аккаунту: TelegramApiServer должен оставаться только во внутренней Docker-сети. Telegram отдельно предупреждает, что неофициальные клиенты наблюдаются на предмет злоупотреблений; автопостинг в собственный канал допустим по назначению, но спам и искусственное увеличение метрик ведут к блокировке: [Obtaining api_id](https://core.telegram.org/api/obtaining_api_id), [API Terms](https://core.telegram.org/api/terms).
- Custom emoji не входят в эту задачу: для них потребуется отдельное сохранение и отправка MTProto-сущностей.
